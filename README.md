# TMS570 FreeRTOS ECU

Firmware for a vehicle ECU (Electronic Control Unit) running on a **Texas Instruments TMS570LS1224** microcontroller with **FreeRTOS**. The ECU is designed for a Formula Student–style electric vehicle, managing dual motor controllers, battery monitoring, vehicle dynamics sensors, RF telemetry, and a touchscreen dashboard.

---

## Hardware Overview

| Component | Details |
|---|---|
| MCU | TMS570LS1224 (ARM Cortex-R4F, 180 MHz) |
| OS | FreeRTOS 7.4.0 |
| Display | Bridgetek FT81x (WQVGA 800×480, via SPI4) |
| RF Module | XBee (via SCI/UART at 115200 baud) |
| Vehicle Network | CAN1 (10 mailboxes) |

### `app/`

Application-level source files written for this project. This is the main starting point for understanding the firmware.

| File | Purpose |
|---|---|
| `App.cpp` | Entry point (`vAppInit`), all FreeRTOS task definitions, ISR notification callbacks |
| `data.cpp` | Global CAN data structures and `update_data()` — reads CAN mailboxes |
| `dashboard.cpp` | Dashboard rendering logic; updates the FT81x display |
| `pages.cpp` | Page/screen management (RACE, TELEMETRY, GRAPH, DEBUG pages) |
| `ui_touch.cpp` | Touch screen input handling and swipe detection |
| `ui_buttons.cpp` | On-screen button rendering (drive enable, traction control, mode) |
| `ui_rpm_bar.cpp` | RPM bar gauge widget |
| `test_main_ecu.cpp` | Simulation mode — injects fake CAN data for bench testing |

See [`docs/rtos_tasks.md`](docs/rtos_tasks.md) for a detailed description of every FreeRTOS task.

### `drivers/`

Peripheral driver configuration files. These configure the TMS570 hardware peripherals for this specific application. They are initially generated by HALCoGen but are customized and maintained by hand.

| File | Peripheral |
|---|---|
| `can.c` | CAN1 — 10 mailboxes, 7-prescaler bit timing, interrupt-driven Rx/Tx |
| `gio.c` | GIO — General-purpose I/O |
| `rti.c` | RTI — Real-Time Interrupt, drives 30/50/60 Hz periodic events |
| `sci.c` | SCI/UART — 115200 baud, XBee RF module |
| `spi.c` | SPI4 — Display controller (FT81x) |

### `halcogen/`

Files generated by the **HALCoGen** tool (see below). These should generally not be edited by hand. If peripheral configuration needs to change, regenerate via HALCoGen and re-apply any manual customizations.

Key files:
- `sys_main.c` — C entry point; calls `vAppInit()`
- `sys_startup.c` — Reset handler, PBIST memory self-test, ECC checks, memory init
- `sys_link.cmd` — Linker script (memory map: VECTORS, KERNEL, FLASH0, STACKS, KRAM, RAM)
- `sys_core.asm`, `sys_intvecs.asm`, `sys_mpu.asm`, `sys_pmu.asm` — ARM core startup and vector table
- `sys_vim.c` — Vectored Interrupt Manager (VIM) setup
- `Device_TMS570LS12.c` — Device-level clock, PLL, and peripheral initialization
- `notification.c` — Weak ISR callback stubs (overridden in `app/App.cpp`)
- `esm.c` — Error Signal Module (safety error handling)
- `sys_selftest.c`, `errata_SSWF021_45.c` — PBIST self-test and silicon errata workarounds

### `rtos/`

FreeRTOS kernel source for the ARM Cortex-R4F port. These files are upstream FreeRTOS and should not need modification. The kernel is configured via `include/FreeRTOSConfig.h`.

Key settings (in `FreeRTOSConfig.h`):
- 8 priority levels (`configMAX_PRIORITIES = 8`)
- 100 kHz tick rate
- Static memory allocation only (`configSUPPORT_STATIC_ALLOCATION = 1`)
- MPU support enabled

### `ti_fee/`

Texas Instruments **Fee (Flash EEPROM Emulation)** library. Provides persistent key-value storage in internal Flash, used here to save and restore touch-screen calibration data across power cycles.

- `ti_fee_ini.c` — Initialization
- `ti_fee_read.c`, `ti_fee_readSync.c` — Read operations
- `ti_fee_writeAsync.c`, `ti_fee_writeSync.c` — Write operations
- `Fapi_UserDefinedFunctions.c` — Required user callbacks for the F021 Flash API

### `ft81x_driver/`

Bridgetek EVE2 display driver for the FT81x graphics controller. Communicates over SPI4. Provides graphics primitives, touch detection, and calibration. This driver is maintained separately from the HALCoGen files and adapts the Bridgetek reference driver to the TMS570 SPI HAL.

### `cobs/`

COBS (Consistent Overhead Byte Stuffing) framing library, used to frame serial packets on the XBee link. Contains vendored copies of `cobs-c` and `nanocobs` as git submodules alongside the local `cobs.c`/`cobsr.c` implementation files.

### `msgpack/`

MessagePack binary serialization library, intended for packing telemetry payloads. Contains the `msgpack-c` and `cmp` submodules alongside the local headers and sources under `msgpack/include/` and `msgpack/src/`.

### `include/`

Flat directory of all header files. Added to the CCS compiler include search path so that `#include "file.h"` resolves correctly from any source directory. Categories within the flat directory:

- **App**: `dashboard.hpp`, `data.hpp`, `pages.hpp`, `ui_*.hpp`, `test_main_ecu.hpp`, `Constants.h`, `Helpers.h`
- **Drivers**: `can.h`, `gio.h`, `rti.h`, `sci.h`, `spi.h`, plus unused peripherals (`adc.h`, `het.h`, etc.)
- **FreeRTOS**: `FreeRTOS.h`, `FreeRTOSConfig.h`, `os_*.h`
- **HALCoGen system**: `sys_*.h`, `Device_TMS570LS12.h`, `hal_stdtypes.h`, `reg_*.h`
- **TI Fee**: `ti_fee.h`, `ti_fee_cfg.h`, `ti_fee_types.h`, `fee_interface.h`
- **F021 Flash API**: `F021.h`, `FapiFunctions.h`, `Registers*.h`, `Types.h`, `MemMap.h`

### `lib/`

Pre-compiled Texas Instruments F021 Flash API static libraries (`.lib`) for Cortex-R4F big-endian. Linked by `sys_link.cmd`. Do not modify.

### `targetConfigs/`

Code Composer Studio target configuration (`TMS570LS1224.ccxml`). Used by the CCS debugger to identify the device and select the appropriate debug probe configuration.

## What is HALCoGen?

**HALCoGen** (Hardware Abstraction Layer Code Generator) is a Texas Instruments GUI tool that generates peripheral driver source code for TMS570 microcontrollers. It reads a project configuration file (`.hcg`) and produces C source files that configure clocks, interrupts, and peripheral registers.

The `.hcg` and `.dil` files at the repo root are the HALCoGen project inputs. The generated output lives in `halcogen/` and `drivers/` (drivers are seeded by HALCoGen but maintained by hand). The `include/reg_*.h` and `include/sys_*.h` headers are also part of the HALCoGen output.

**Workflow:**
1. Open `tms570_freertos_test.hcg` in HALCoGen.
2. Change peripheral settings in the GUI.
3. Generate code — HALCoGen overwrites the files in `halcogen/` and `drivers/`.
4. Re-apply any manual customizations (especially in `drivers/rti.c`, which is modified to co-exist with the FreeRTOS tick).

> The RTI driver (`drivers/rti.c`) is a special case: HALCoGen generates it, but it is then modified to avoid a conflict with FreeRTOS's `prvSetupTimerInterrupt()`, which also uses RTI Counter 0 Compare 0.

## CCS Project Setup

The CCS project files (`.project`, `.cproject`) are excluded from the repository via `.gitignore` because they contain machine-specific absolute paths. To recreate the project:

1. Create a new CCS project targeting the TMS570LS1224.
2. Add the following **source directories** to the build:
   - `app/`
   - `drivers/`
   - `halcogen/`
   - `rtos/`
   - `ti_fee/`
   - `ft81x_driver/`
   - `cobs/`
   - `msgpack/src/`
3. Add the following **include search paths**:
   - `include/`
   - `ft81x_driver/`
   - `msgpack/include/`
4. Link the libraries in `lib/` appropriate for your build variant (NDS or V3D16).
5. Set the linker command file to `halcogen/sys_link.cmd`.

## Data Flow

```
CAN Bus (sensors, motor controllers)
    │
    ▼
canMessageNotification() [ISR]
    │ sets EVT_CAN_* bits
    ▼
vDataUpdateTask (60 Hz)  ──► update_data() ──► global data structs
    │                                           (sensors_data, speed_data, ...)
    │ sets EVT_NEW_DATA
    ▼
vRulesTask ──► compliance checks ──► sets EVT_DATA_APPROVED
    │
    ▼
vDriversFSMTask ──► motor driver state machine ──► CAN Tx (motor commands)

vTelemetryTask (50 Hz) ──► pack data ──► sciSend() ──► XBee RF

vDisplayTask (30 Hz) ──► update_dashboard_draw() ──► FT81x SPI
```
